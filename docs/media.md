# Загрузка и удаление медиа

Медиа-API находится в существующих группах `/api/authors`, `/api/users`,
`/api/sections`, `/api/books`. Отдельного ключа клиентов нет: доступ при
размещении обеспечивает авторизация админки. Точные схемы — в `openapi.yaml`.

## Подготовка

В существующем `.env` добавлены настройки S3. Заполните `S3_ACCESS_KEY_ID` и
`S3_SECRET_ACCESS_KEY` ключами аккаунта Object Storage с правами чтения,
записи и удаления объектов бакета. Чтение необходимо для временных копий
при замене и удалении. `.env` и `.env.development` исключены из Git и
Docker build context; `.env.example` содержит только шаблон без секретов.
Compose передаёт настройки контейнеру через переменные окружения.

Параметры `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_PUBLIC_BASE_URL`
обязательны: сервер читает их только из окружения. Значения для целевого
бакета указаны в `.env.example`; перенесите их в локальный `.env`.
В коде и Compose запасных адресов нет. Если параметр отсутствует или пуст,
сервер сообщает, какой параметр нужно настроить.

Панель управления целевым бакетом:
https://msk.cloud.vk.ru/app/mcs6976552820/services/storage/buckets/bookreader

Адрес панели не является S3 endpoint. `S3_PUBLIC_BASE_URL` задаёт адрес
прямых ссылок, включая возможный CDN; endpoint используется для подписанных
запросов к S3. Публичное чтение объектов нужно настроить на стороне бакета/CDN.
Сам сервер не меняет политику доступа бакета.

Для появления `preview_url` у авторов, пользователей и разделов выполнить
миграцию `AddMediaPreviews` обычной командой `swift run App migrate --yes`
или Compose-сервисом `migrate`. Миграция не меняет существующие ссылки.
На macOS изображения обрабатываются ImageIO/CoreGraphics. Linux-контейнер
содержит ImageMagick; при запуске Linux вне Docker установить его и указать
путь к `convert` в `MEDIA_IMAGE_CONVERTER`. На macOS этот обработчик также
можно выбрать при сборке флагом `-Xswiftc -DMEDIA_USE_IMAGEMAGICK`.

## Методы

| Сущность | Путь для POST и DELETE |
|---|---|
| Автор | `/api/authors/{authorID}/image` |
| Пользователь | `/api/users/{userID}/image` |
| Раздел | `/api/sections/{sectionID}/image` |
| Книга | `/api/books/{bookID}/image` |
| Изображение главы | `/api/books/{bookID}/chapters/{chapterID}/image` |
| Аудио главы | `/api/books/{bookID}/chapters/{chapterID}/audio` |

`POST` принимает **один бинарный файл в теле**, без JSON, base64 или
multipart-обёртки. `Content-Type` обязателен. Для изображений: `image/jpeg`,
`image/png`, `image/webp`, до 20 MiB. Для аудио: `audio/mpeg` (MP3) и
`audio/mp4`, `audio/m4a`, `audio/x-m4a` (M4A), до 1 GiB. Лимит проверяется
также при отсутствии `Content-Length`. Формат проверяется по сигнатуре;
изображение дополнительно декодируется. Аудио не перекодируется, проверка
заголовка не заменяет полную проверку аудиопотока.

Для обоих видов медиа главы обязателен query-параметр `chapterNumber`
(целое число от 1). В имя включается `chapter_01`; номера больше 99
не обрезаются. Глава должна принадлежать указанной книге.

```sh
curl --fail-with-body -X POST \
  -H 'Content-Type: image/png' \
  --data-binary @portrait.png \
  'http://localhost:8080/api/authors/AUTHOR_UUID/image'

curl --fail-with-body -X POST \
  -H 'Content-Type: audio/mpeg' \
  --data-binary @chapter.mp3 \
  'http://localhost:8080/api/books/BOOK_UUID/chapters/CHAPTER_UUID/audio?chapterNumber=1'
```

Базовое изображение: PNG, не более 1024 px по большой стороне, исходник
меньшего размера не увеличивается. Превью: центральный квадрат базового
изображения, 96×96 px, JPEG quality 80. Прозрачность превью заменяется белым
фоном. Сохраняется первый кадр, учитывается EXIF-ориентация, метаданные
удаляются. Ориентировочный вес превью 3–4 КБ не гарантируется фиксированным
качеством: он зависит от изображения.

Успешная загрузка возвращает HTTP 200:

```json
{"success":true,"url":"https://…/tolstoy_lev.png","previewUrl":"https://…/tolstoy_lev_mini.jpg"}
```

Для аудио поле `previewUrl` отсутствует. Удаление принимает JSON с прямой
ссылкой на текущий файл:

```sh
curl --fail-with-body -X DELETE \
  -H 'Content-Type: application/json' \
  --data '{"url":"https://MEDIA_PUBLIC_HOST/authors/tolstoy/tolstoy_lev_mini.jpg"}' \
  'http://localhost:8080/api/authors/AUTHOR_UUID/image'
```

Ссылка на оригинал **или** превью удаляет оба файла и очищает ссылки в базе.
Для удаления `chapterNumber` не нужен. URL проверяется по настроенному
бакету и ссылкам сущности; произвольные внешние URL, URL с query/fragment и
ссылки другой сущности не принимаются. Допустимы публичный адрес,
path-style адрес `S3_ENDPOINT/bucket/key` и virtual-host адрес бакета.
Отсутствующий объект S3 считается удалённым. Повторное удаление уже
отвязанной ссылки возвращает HTTP 400. Успех: `{"success":true}`.

Ошибки используют стандартный формат Vapor `{"error":true,"reason":"…"}`.
OpenAPI описывает статусы 400, 404, 413, 415, 422, 500, 502, 503.

## Именование и замена

Латиница получается через ICU-транслитерацию и удаление диакритики.
Регистр нижний; группы символов вне `a-z0-9` заменяются `_`.
Пустые имена и части имени длиннее 200 байт отклоняются.
Изображения больше 100 мегапикселей или 20000 px по стороне отклоняются.
Коллизии считаются исключёнными проверками самих сущностей.

```text
authors/tolstoy/tolstoy_lev.png
authors/tolstoy/tolstoy_lev_mini.jpg
users/polina.png
users/polina_mini.jpg
sections/classics/classics.png
sections/classics/classics_mini.jpg

audiobooks/lev_tolstoj/vojna_i_mir/lev_tolstoj_vojna_i_mir.png
audiobooks/lev_tolstoj/vojna_i_mir/lev_tolstoj_vojna_i_mir_mini.jpg
audiobooks/lev_tolstoj/vojna_i_mir/lev_tolstoj_vojna_i_mir_chapter_01.mp3
audiobooks/lev_tolstoj/vojna_i_mir/lev_tolstoj_vojna_i_mir_chapter_01.png
audiobooks/lev_tolstoj/vojna_i_mir/lev_tolstoj_vojna_i_mir_chapter_01_mini.jpg
```

Конкретное написание латиницей определяет ICU; оригинальное имя файла
клиента не используется. Для книги выбирается первая привязанная роль
`author` по `createDate`, затем UUID. Если таких ролей нет, используется
`Book.authorId`. Пользователь-публикатор не подменяет автора произведения.
Эти правила также применяются к сезонам и выпускам подкастов.

Загрузка синхронная: приём на диск → проверка/обработка → S3 → обновление
ссылок → удаление прежних объектов → фиксация транзакции → HTTP-ответ.
Переименование само по себе не перемещает файлы. При обновлении авторов,
пользователей и разделов без полей медиа прежние ссылки сохраняются. При следующей загрузке
путь строится по текущим именам, а прежние файлы находятся по ссылкам,
прочитанным из базы. Базовое изображение заменяется вместе с превью.

Строка сущности блокируется записью ID без изменения его значения через
Fluent внутри транзакции на время работы с S3 и базой. Все операции с базой
используют Fluent; прямых SQL-запросов нет. На время операции существующие объекты копируются на локальный
диск; при ошибке выполняется компенсация изменений в S3. Неполное
восстановление явно сообщается в `reason`. S3 и PostgreSQL не образуют
единой атомарной транзакции: аварийное завершение процесса или длительная
недоступность S3 могут потребовать сверки объектов и ссылок.

Временная папка запроса удаляется после успеха или ошибки, включая обрыв
приёма. После аварийного завершения процесса могут остаться папки UUID;
удалять их следует при остановленном сервере. При замене аудио предусмотреть
место для нового файла и временных копий старых объектов. Reverse proxy
должен пропускать тело до 1 GiB и позволять длительные синхронные запросы.
Настройки nginx и живого бакета этим изменением не меняются.
