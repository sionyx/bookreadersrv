# Адреса разделов, книг и авторов

`link_name` — каноническое короткое имя для URL, уникальное внутри типа
сущности. UUID остаются в `id`, `parentId`, `authorId`, `sectionId`, `bookId`
и других полях связей; это идентификаторы данных, а не адреса для навигации.

- `GET /api/books/{UUID или link_name}` возвращает `link_name`,
  `author_link_name`, `section_link_name`, а также `roles[].author.link_name`.
- `GET /api/authors/{UUID или link_name}` возвращает автора и `books` со всеми
  его неудалёнными книгами без дублей, включая соавторство и старые записи
  только с основным `authorId`. Для ссылок используются `books[].link_name`.
- Разделы, списки, поиск, содержимое раздела и путь до раздела возвращают
  `link_name`. Старое поле раздела `name` больше не выдаётся, но принимается
  при записи как совместимый псевдоним; `link_name` имеет приоритет.
- GET/PUT/DELETE сущностей, их медиа, `/api/info/...` и `/app/...` поддерживают
  оба адреса. UUID пользователя/главы не заменяются именем книги или автора.
- Сгенерированные ссылки в серверных шаблонах используют `link_name`.
  Избранные карточки root.leaf разрешают сохранённые UUID в текущие link_name
  при рендеринге; для отсутствующей записи ссылка ведёт в корневой каталог.

При создании адрес необязателен: транслитерация названия книги/раздела или
имени и фамилии автора, нижний регистр, дефисы вместо пробелов. Коллизии
получают `-2`, `-3` и т. д.; удалённые книги резервируют свои адреса.
Явный адрес: 1–160 символов `[a-z0-9]` с одиночными разделителями `-`/`_`;
UUID и служебные `search`, `path` запрещены. Занятый адрес — HTTP 409,
неверный формат — HTTP 400. Уникальность дополнительно защищена в БД.

При обновлении без `link_name` существующий адрес сохраняется, даже если
изменилось название. Для изменения адреса нужно явно передать `link_name`.
Старый адрес после этого не является алиасом; UUID продолжает работать.
Медиа не перемещаются при изменении адреса. Следующая загрузка изображения
раздела использует новое имя; старые объекты удаляются по сохранённым URL.

## Миграция

Перед запуском новой версии выполнить `swift run App migrate --yes`
(или Compose-сервис `migrate`) с резервной копией БД и остановленной записью.
`AddLinkNames` через Fluent, внутри одной транзакции:

1. Создаёт `link_name` для трёх таблиц.
2. Сохраняет прежние `sections.name` без изменения; неверные/повторяющиеся
   адреса разделов приводят к отмене миграции с описанием причины.
3. Заполняет авторов и книги транслитерацией, разрешая совпадения суффиксами
   в детерминированном порядке UUID. Включает мягко удалённые книги.
4. Добавляет уникальные ограничения и удаляет прежнюю колонку `sections.name`.

Откат миграции возвращает `sections.name` из текущего `link_name` и удаляет
новые поля. Перед возвратом старого образа нужно откатить миграцию;
старый код несовместим с переименованной колонкой. Откат удаляет адреса
книг/авторов, поэтому перед ним также нужна резервная копия.

Полный контракт — `docs/openapi.yaml`. Клиентам сайта и MCP нужно заново
сгенерировать типы/схемы и перейти с `section.name` на `section.link_name`;
эта серверная доработка сама по себе не меняет клиентский код.
